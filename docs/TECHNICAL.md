# 🛠️ 技術仕様書・設計ドキュメント (TECHNICAL.md)

このドキュメントは、**Tukinoma Bot** の内部構造、データ管理の仕組み、および各モジュールの役割を解説した技術仕様書です。  
人間の開発者がコードを把握・メンテナンスしやすくすることはもちろん、AI（LLM）にプロジェクト構造を理解させる際のコンテキストとしても活用できます。

---

## 1. 全体アーキテクチャ（設計思想）

Bot全体の基本構造は**「壊れにくく、後から機能を増やしやすい」**ように設計されています。

### 💡 3つの設計ポイント

1. **機能ごとの独立化 (Cogパターン)**
   - VC通知機能やメッセージ削除機能など、機能ごとに `cogs/` フォルダ配下へファイルを分けて作成しています。
   - これにより、1つの機能を修正しても他の機能に影響（バグ）が出ない仕組みになっています。

2. **データ管理の集約化 (`ConfigManager`)**
   - 設定ファイル（JSON）の読み込み・保存処理を、各機能から直接行わず `ConfigManager` という専用のクラスに任せています。
   - **メリット**: 将来的にデータの保存先を JSON からデータベース（SQLiteやPostgreSQL等）に切り替えたくなった場合でも、このマネージャークラス1つを書き換えるだけで対応可能です。

3. **設定ファイルの分離**
   - `data/` フォルダ内に `data/vc_notifier.json` のように機能単位でファイルを分けて保存します。
   - 万が一1つの設定ファイルが破損しても、Bot全体のデータが巻き込まれて消えるリスクを回避できます。
